# Changelog

All notable changes to Dorothea are documented here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project uses
[Semantic Versioning](https://semver.org/).

## [Unreleased]

### Added
- Captions from the photo itself (#51): the title and description Lightroom, Capture One, Apple
  Photos, darktable and others store in the file (XMP, else IPTC) become the photo's caption,
  the title as a heading above the description, and its title in the gallery's feed, when the
  photo has no caption file; a `.md` or `.txt` caption replaces them entirely. On by default (`embedded_captions`), off with `--legacy`; read once per photo and
  cached. EXIF's ImageDescription isn't used, since cameras fill it with their model name.
- `dorothea check` (#46): looks through the settings, every `gallery.yml` / `metadata.txt` and
  every caption without building, and lists mistakes with their file and line: unknown keys
  (suggesting the one you probably meant; the theme's keys are the placeholders in its
  `post-template.html`, so custom themes are covered), gallery-only keys like `sort:` in a
  caption, values Dorothea can't use (`sort: random`, `date: next tuesday`), keys set twice,
  caption text before the metadata, captions that match no photo, and gallery files that are
  ignored. Exits with 1 if it finds anything, so it can guard a build in CI.
- Documentation site at [dorothea.readthedocs.io](https://dorothea.readthedocs.io/) (#25), with a
  configurator (#30): pick settings in a form and copy or download a `_config.json` that holds
  only what differs from the defaults (from Dorothea's or expose.sh's), or paste an existing one
  to edit it. Values are checked as you type. The settings are also published as a JSON Schema,
  so a `"$schema": "https://dorothea.readthedocs.io/schema/config.json"` line in `_config.json`
  gives completion and checks in editors like VS Code; Dorothea accepts that line.
- Photo details (#20): the new `exif_display` setting shows each photo's camera, lens, focal
  length, aperture, shutter speed and ISO, read from its EXIF (never its location). `"icon"`
  (the default; `"off"` with `--legacy`) puts an ⓘ in a corner of the photo, in its colours,
  whose panel shows on hover or focus and stays open on click or tap; `"caption"` adds a line
  like `Fujifilm X-T4 · 23mm · f/2 · 1/250s · ISO 160` under the photo's text. Captions and
  `metadata.txt` can set `exif: false` / `icon` / `caption`, and override or supply single
  details (`lens: Helios 44-2`, `iso: -` to hide). Custom themes get `{{exif_icon}}`,
  `{{exif_caption}}`, `{{camera}}`, `{{lens}}`, `{{focal_length}}`, `{{aperture}}`,
  `{{shutter_speed}}`, `{{iso}}` and `{{exif_summary}}`. Details are cached in
  `.dorothea-cache.json`. Shown by `photoessay` and `medium`; `theme1`/`theme2` are untouched.
- `photoessay` and `medium` work on phones and in narrow windows (#5). Pages now carry a
  viewport tag, and below 700px wide the fixed minimum widths (which made pages scroll
  sideways) are gone. In `photoessay` the sidebar becomes a bar across the top with a menu
  button for the galleries and controls, and captions sit below their photo at a readable size.
  In `medium` the column widens, the masthead title shrinks, and header links become icons.
  Desktop layouts are unchanged; `theme1`/`theme2` are untouched.
- `tests/data/showcase`, a multi-gallery site for checking theme layouts
  (`make try GALLERY=tests/data/showcase`), generated by `scripts/make_showcase_gallery.py`.
- Whole-gallery downloads (#9): the new `download_album` setting (off by default) writes one zip
  per gallery with its originals and the `download_readme`. `photoessay` and `medium` link it
  ("download all", with its size). The zip is rebuilt only when the gallery's files or the
  readme change, and is listed by `--dry-run`. `download: false` / `download: true` in a
  gallery's `metadata.txt` overrides the setting; turning a gallery's zip off deletes it.
- Atom feed of galleries (#11): with the new `site_url` setting, the build writes `feed.xml`
  (one entry per gallery, newest first, with its first photo and text). Order comes from a
  `date:` in the gallery's `metadata.txt`, else when its newest photo was taken, else file
  times; `description:` sets the entry's text. `photoessay` and `medium` add a feed link to
  the sidebar/header and a `<link rel="alternate">` for feed readers. Each gallery also gets
  its own feed with one entry per photo (`gallery_feeds`, on by default; `feed: false` in a
  gallery's `metadata.txt` opts it out).
- README badges for CI status, tests passing, coverage, lines of code (with and without tests),
  PyPI version, Python versions and license; pull requests get comments with test results
  from every CI job and with coverage and code size compared to `main` (#27). No external
  services: the numbers live on the repository's `badges` branch.
- `dorothea serve` (#6): builds the site (with the same flags as `dorothea`), then previews it
  at http://localhost:8000/, so gallery links (which point at folders) work. `--no-build`,
  `--port`, `--bind`. Supports byte ranges, so videos play in Safari and can be seeked.
- `link_index_html` setting (#6, off by default): gallery links point at `…/index.html`, for
  sites browsed straight from disk or hosted without directory indexes.
- Progress bars on a terminal (#4), drawn with [rich](https://pypi.org/project/rich/) (a new
  dependency): overall "Reading N files" and "Encoding i/N" counts, plus percentage and ETA
  for every video pass (e.g. `vp9 1280px pass 2/2`) and image-sequence compile. Output to
  pipes and logs is unchanged.
- Photos in WebP, AVIF, HEIC/HEIF (iPhone, via [pillow-heif](https://pypi.org/project/pillow-heif/),
  a new dependency) and TIFF are read and published, in both modes (#2).
- New themes `photoessay` (the new default) and `medium`: Dorothea's versions of `theme1` and
  `theme2`, which stay exactly as in expose.sh (and are the `--legacy` default) (#5). Both add
  keyboard navigation between photos: ↓ / Page Down / → / Space / j for next, ↑ / Page Up / ← /
  Shift+Space / k for previous, Home / End for first / last (#16).
- `--ffmpeg auto|bundled|system|PATH` and a matching `ffmpeg` setting choose which ffmpeg
  encodes videos (#3). Builds with videos now print the ffmpeg in use and its version, and warn
  when it lacks an encoder for a configured format (e.g. no libvpx for vp8).
- `sort` setting and `--sort MODE` (#10): `natural` (numbers compare as numbers: `1, 2, 10`),
  `name` (expose.sh's order), `capture` (EXIF capture time, else file time; galleries follow
  their earliest photo), each with a `-desc` variant. A gallery's `metadata.txt` can set `sort:`
  for its own photos.
- `--legacy` / `--no-legacy` and a `legacy` setting (#24): use expose.sh's default settings, so a
  gallery builds exactly the site expose.sh would.
- `textbackground` post metadata (or in `metadata.txt` for a whole gallery) draws a background
  colour behind caption text in both bundled themes (#15). Pages that don't use it are
  unchanged. Captions from `<photo>.md` (as well as `.txt`) are now documented.

### Changed
- **Settings are now in `_config.yml`** (#46), one `setting: value` per line with `#` comments,
  instead of `_config.json`. A `_config.json` stops the build with a reminder to rename it
  (JSON is valid YAML, so it works as it is); expose.sh's `_config.sh` is still read, and
  `--convert-config` now writes `_config.yml`. Only `true`/`false` are yes/no values (YAML 1.2),
  so `exif_display: off` means the "off" choice and dates stay as written. Mistakes are reported
  with their line (`jpeg_quality must be an integer from 1 to 100, got 500 (_config.yml line 3)`),
  unknown settings suggest the one you probably meant (`did you mean site_title?`), and a
  setting with no value (`site_url:`) keeps its default, with a note. The docs' configurator
  writes and reads `_config.yml`, and a `# yaml-language-server: $schema=…` line at the top
  gives completion and checks in VS Code's YAML extension.
- **Markdown captions** (#52): a `.md` caption can start with YAML front matter (settings
  between `---` lines, as in Jekyll, Hugo or Obsidian), read like `_config.yml`. `.txt`
  captions, and `.md` ones without front matter, are read line by line as before, and with
  `--legacy` every caption is. Front matter YAML can't read, or where it would lose a value (an
  unquoted `textcolor: #ff9518` reads as a comment), is read the old way, with a warning naming
  the line to fix. `--convert-config` turns `.txt` captions into `.md` ones (quoting what needs
  it, keeping comments, and checking the result reads the same before deleting the original);
  `dorothea check` checks front matter keys with their lines. When a photo has both a `.md` and
  a `.txt` caption, the `.md` is now used (the `.txt` was), except with `--legacy`, which keeps
  expose.sh's order; `check` reports the one that isn't.
- **Gallery settings can go in `gallery.yml`** (#46), YAML like `_config.yml`, instead of
  `metadata.txt`, which still works (if a folder has both, `gallery.yml` is used). Lists such
  as theme1's `polygon` reach the theme as JSON; multi-line `description:` text keeps its
  paragraphs in the feed. Lines starting with `#` are now comments in `metadata.txt` and caption
  metadata too, instead of being warned about as caption text; expose.sh ignored them as well,
  so pages don't change. `--convert-config` now also turns every `metadata.txt` into a
  `gallery.yml` (keeping comments, quoting values YAML would read differently), and deletes
  each original, `_config.sh` included, once the new file gives exactly the same settings;
  what it can't convert that way is left alone, with a note.
- New defaults (#24; `--legacy` restores expose.sh's): `sort` is `natural` (was `name`),
  `video_formats` is `["h264", "vp9"]` (was vp8), `h264_encodespeed` is `slow` (was `veryslow`),
  and `social_button` is off (was on). Existing galleries without these settings pick them up
  on the next build; only the affected files (e.g. the new vp9 videos) are re-encoded.
- Resized photos can keep their metadata (#12): `keep_metadata` is `none`, `copyright`,
  `camera` (the new default: copyright plus camera, lens and exposure settings, never location),
  `location`, `cameralocation` or `all`. Wide-gamut photos (Display P3, Adobe RGB) are converted
  to sRGB instead of losing their colour profile and looking dull (`convert_to_srgb`, on by
  default). `--legacy` keeps expose.sh's behaviour: strip everything, no conversion.
- The command line is built with [click](https://click.palletsprojects.com/): same options,
  clearer `--help`, `-h` works too.

### Fixed
- `photoessay`: the sidebar icons (site camera, resolution, hide text, feed, download, share)
  showed as plain squares in browsers that no longer support the old
  `-webkit-mask-box-image` property. They now use standard CSS masks, still tinted with the
  photo's colours, and the browser sniffing that chose between the two is gone. The sidebar is
  wider (200px instead of 170px) so a site title or gallery name no longer runs into its edge,
  and a single word too long for it breaks instead. `theme1` is unchanged.
- `photoessay`: opening a link to a particular photo (`gallery/#4`, as gallery feed entries
  use) scrolls to that photo in Firefox too; it stayed at the top, because the slides only get
  their height once the page's script runs.
- Caption file mistakes no longer fail silently (#17): text placed before the metadata block
  (which is dropped, as in expose.sh) now prints a warning naming the file; `---` separators
  with trailing spaces are recognised, instead of the metadata showing up in the caption; a
  UTF-8 byte-order mark before the first `---` no longer hides that separator.
- Windows support (#19): Windows' own `convert.exe` (a disk tool in System32) is no longer
  mistaken for ImageMagick, so colours and `image-options` work (with or without ImageMagick);
  2-pass video encodes no longer write to `/dev/null`; tool output and console messages don't
  fail on non-ASCII names. CI now runs the tests on Windows.
- With ImageMagick 7, its `magick` command is used, so builds no longer print "The convert
  command is deprecated" warnings. Output is byte-identical.
- Videos with audio (`disable_audio: false`) are built in every format again (#13). Audio was
  always copied, so AAC from phone/camera videos made every WebM (vp8/vp9) and Ogg encode fail;
  it's now copied only where the container allows it and re-encoded otherwise (Opus for WebM,
  Vorbis for Ogg, AAC for MP4). A format that fails to encode is now reported
  (`vp9: skipped for …`) instead of only showing ffmpeg's error.
- GIFs (including animated ones: first frame), palette PNGs, transparent PNGs and 16-bit images
  produce resized JPEGs again instead of "cannot write mode P/RGBA as JPEG" (#2). Transparency
  is dropped the way ImageMagick does it.
- `--version` always shows the name the command was invoked as (`dorothea`, `expose` or
  `python -m dorothea`).
- Folder and file names in non-Latin scripts get proper URLs (`москва`, `北京`, `café-zürich`)
  instead of empty ones, which crashed the build by trying to write to the filesystem root
  (#18). Output paths are now checked to stay inside `_site`.
- A hidden folder inside a gallery (`.thumbs`, `.git`) no longer makes the gallery's photos
  disappear; hidden files and macOS `._` files are no longer published, including inside image
  sequences; a folder holding only hidden files isn't shown as an empty gallery (#7).
- Files or galleries whose names map to the same URL (`01 photo.jpg` / `02 photo.jpg`,
  `Photo.jpg` / `photo.png`, two `Iceland` folders side by side) no longer overwrite each other.
  The earliest photo (EXIF capture time, else file time) keeps the URL and the others get `-2`,
  `-3`, …, with a warning (#8). EXIF is read with [ExifRead](https://pypi.org/project/ExifRead/),
  a new dependency.

## [1.9.0] - 2026-09-27

Releases 1.9.x are the run-up to 2.0.0 while the first release is fine-tuned; 2.0.0 marks it
stable.

First release of Dorothea, a Python port of expose.sh that produces the same site
(identical HTML/CSS/JS, same-size images and videos) for the same photos and settings.

### Added
- `dorothea` command (also installed as `expose`), runnable with `uvx dorothea` or
  `pipx run dorothea`, with themes bundled in the package.
- Command-line options: `-n/--dry-run`, `-c/--config FILE`, `-s/--set KEY=VALUE`, `-j/--jobs N`,
  `--convert-config`, `--version`.
- `_config.json` configuration, validated with readable errors. expose.sh's `_config.sh` is
  still read (safely, never executed), and `--convert-config` converts it.
- Incremental builds: each output's fingerprint (source, settings, per-post metadata) is kept
  in `.dorothea-cache.json`, so only affected files are rebuilt. Colour palettes are cached too.
- Parallel image processing (one worker per CPU by default).
- `CONFIG.md` (every setting) and `MIGRATION.md` (coming from expose.sh).
- CI on GitHub Actions: lint (ruff, ty), full tests plus parity against expose.sh, a run
  without any system packages, and a packaging check that runs the built wheel and sdist
  through `uvx`/`pipx`. Releases publish to PyPI with trusted publishing.

### Changed
- No system packages required: Pillow replaces ImageMagick for resizing, python-markdown
  replaces Markdown.pl, and ffmpeg comes from imageio-ffmpeg (a system ffmpeg is preferred when
  installed). ffprobe is no longer used. ImageMagick is optional (colour extraction,
  `image-options`).
- Requires Python 3.14+.
- Outputs are written atomically, so failed or interrupted encodes are retried instead of
  leaving truncated files.
- 2-pass ffmpeg logs go to a temporary folder instead of the gallery folder.

### Fixed
- `image-options` and `video-options` post metadata are applied (they were parsed but ignored).
- Image sequences mixing formats or extensions (`.JPG`/`.jpg`, JPEG/PNG) keep every frame.
- Resized JPEGs use the same chroma subsampling as ImageMagick 7 (they were ~11% larger).
- Caption Markdown matches Markdown.pl's output (lists, line breaks, images, `>`).
- A corrupt photo, a failing ffmpeg run, or a non-UTF-8 caption file no longer aborts the build.
- Very detailed images no longer crash JPEG writing ("broken data stream").
- Captions and pages are always UTF-8, whatever the system locale.
